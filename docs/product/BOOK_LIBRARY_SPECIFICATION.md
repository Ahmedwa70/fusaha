# الدليل المرجعي لإضافة الكتب والمراجع إلى فُصحاء

### الحالة والنطاق

- **نوع الوثيقة:** مرجع تنظيمي لإدارة الكتب والمراجع التعليمية.
- **الحالة:** مسودة معتمدة للاستخدام التنظيمي، وقراراتها التقنية مؤجلة.
- **العلاقة بالرؤية:** تفصيل تنظيمي لمنتج «مكتبة الموارد التعليمية» الوارد في [`VISION.md`](./VISION.md).

> **تنبيه مهم:** هذا الدليل يحدد طريقة تنظيم الكتب وتصنيفها وتوثيقها. لا يعني ذكر أي وظيفة هنا أنها منفذة في المنصة. ما هو قائم فعليًا موضح في القسم 0، وكل ما عداه مقترح أو مستقبلي ما لم يُثبت تنفيذه.

## 0. الوضع الحالي في المستودع

نتيجة فحص الوثائق والبنية عند كتابة هذا الدليل:

| البند | الحالة |
|---|---|
| مكتبة كتب أو مراجع داخل المنصة | **غير موجودة.** لا توجد صفحات أو جداول أو خدمات لإدارة الكتب. |
| جداول قاعدة البيانات للكتب أو السلاسل أو الملفات | **غير موجودة.** مخطط `database/schema/` يغطي الدروس ونسخها والمجلدات والرصيد والصلاحيات والإعدادات، ولا يتضمن كيانات للكتب. |
| رفع ملفات PDF وDOCX | **موجود كمصدر لإنشاء درس فقط.** يُستخرج النص في `lib/ai/extract-file-text.ts` ثم يُستخدم في التوليد، مع حد أقصى صفحتين لملف PDF (`MAX_PDF_PAGES = 2`). انظر [`ai-pipeline.md`](../ai-pipeline.md). |
| تخزين الملفات الأصلية | **قرار مفتوح.** يذكر [`PRD.md`](../PRD.md) تخزين الملفات بوصفه مسألة لم تُحسم. |
| عرض ملفات PDF داخل المنصة | **غير موثق ولا يظهر كوظيفة قائمة.** |
| ذكر CEFR في الوثائق الحالية | **غير موجود.** المثال الوارد في القسم 11 توضيحي. |

النتيجة: آلية استخراج النص من ملف قصير لإنشاء درس لا تمثل مكتبة كتب. لذلك يُعامل هذا الدليل بوصفه معيارًا تنظيميًا يُطبق يدويًا الآن، ويوجّه أي تنفيذ تقني لاحق.

## 1. الغرض من الدليل

يحدد هذا الدليل معيارًا موحدًا لإضافة أي كتاب أو مرجع تعليمي إلى فُصحاء، بهدف:

- منع الفوضى وتكرار الملفات وتعدد النسخ غير الموثقة.
- تسهيل البحث عن المادة واسترجاعها من أكثر من مدخل.
- حفظ العلاقة بين الكتاب وسلسلته وملحقاته بدل تسجيل كل ملف منفردًا.
- توضيح حقوق الاستخدام قبل أي إتاحة.
- تمهيد الربط المستقبلي بين المكتبة وأدوات فُصحاء التعليمية.

الدليل مرجع تنظيمي، لا وصف لوظائف منفذة.

## 3. التصنيف الرئيسي للمكتبة

| القسم | الغرض | أمثلة توضيحية |
|---|---|---|
| **1. مكتبة المتعلم** | مواد يستخدمها الطالب مباشرة | كتب الطالب، القصص المتدرجة، كتب المفردات المصورة |
| **2. مكتبة المعلم** | مواد تدعم التخطيط والتدريس | كتب المعلم، الأدلة، الشروح، مفاتيح الإجابات |
| **3. مكتبة المعايير والمراجع الأساسية** | مرجعية للمستويات والمحتوى اللغوي | الأطر المرجعية للمستويات، كتب النحو، المعاجم |
| **4. مكتبة المواد التعليمية العملية** | مواد جاهزة للاستخدام الصفي | كراسات التمارين، الاختبارات، البطاقات، مواد فُصحاء |

القسم الرئيسي لا يكفي وحده. يُضاف إلى كل سجل بيانات وصفية (القسم 4) ووسوم حرة مضبوطة، مثل المهارة والموضوع والفئة العمرية، حتى يمكن العثور على الكتاب من مداخل متعددة. مثال: كتاب قصص للأطفال يقع في «مكتبة المتعلم»، ويحمل وسوم `قراءة` و`أطفال` و`مبتدئ`.

## 4. معيار بيانات كل كتاب

### الحقول الإلزامية

| الحقل | الوصف | عند غياب المعلومة |
|---|---|---|
| المعرّف الداخلي | معرف فريد ثابت لا يتغير، مثل `FSH-BK-0001` | لا يُقبل السجل دونه |
| العنوان | عنوان الكتاب كما يظهر على الغلاف | يُكتب العنوان الظاهر في الملف مع حالة «يحتاج إلى مراجعة» |
| نوع المادة | أحد أنواع القسم 2 | «يحتاج إلى مراجعة» |
| القسم الرئيسي | أحد أقسام القسم 3 | «يحتاج إلى مراجعة» |
| لغة المحتوى الفعلية | لغة المتن، مثل العربية أو العربية مع الإنجليزية | تُحدد بعد فتح الملف |
| اسم الملف وصيغته | الاسم الموحد والصيغة، مثل PDF | لا يُقبل السجل دونه |
| المصدر | الجهة أو الشخص أو الرابط الذي جاء منه الملف | «غير معروف» ويُعلّق النشر |
| حالة الحقوق والترخيص | إحدى حالات القسم 8 | «غير واضح الحقوق» تلقائيًا |
| حالة المراجعة | `مسودة` أو `قيد المراجعة` أو `معتمد` أو `معلّق` | `مسودة` |
| تاريخ الإضافة | تاريخ تسجيل المادة | يُسجل عند الإضافة |

### الحقول الموصى بها

| الحقل | الوصف |
|---|---|
| العنوان الأصلي | إذا اختلف عن العنوان المعروض أو كان بلغة أخرى |
| المؤلف أو المؤلفون | كما يظهرون في الكتاب |
| الناشر | الجهة الناشرة |
| سنة النشر والطبعة | من صفحة الحقوق |
| الجمهور المستهدف | أطفال، يافعون، بالغون، معلمون، ناطقون بغير العربية |
| المجال أو المهارة | قراءة، كتابة، استماع، محادثة، مفردات، قواعد |
| وصف موجز | سطران إلى ثلاثة أسطر عن المحتوى والاستخدام |
| الوسوم | كلمات مضبوطة للتصفية |
| آخر تحديث | تاريخ آخر تعديل على السجل أو الملف |

### الحقول المشروطة بنوع الكتاب

| الحقل | متى يُطلب |
|---|---|
| المستوى اللغوي | للكتب المنهجية وكتب الطالب والقراءة المتدرجة |
| السلسلة أو المنهج | إذا كان الكتاب جزءًا من سلسلة |
| الجزء أو المستوى داخل السلسلة | للسلاسل متعددة الأجزاء |
| المواد المرتبطة | لكتب الطالب والمعلم والملاحق |
| نوع الملحق | للملاحق: صوت، إجابات، بطاقات، شرائح |
| الإطار المرجعي ونسخته | للمعايير والأطر المرجعية |

**قاعدة ثابتة:** لا تُخترع معلومة ناقصة. تُستخدم «غير معروف» عندما لا يمكن الحصول على المعلومة، و«يحتاج إلى مراجعة» عندما يمكن التحقق منها لاحقًا.

## 5. العلاقة بين السلسلة والكتاب والوحدة والملف

### النموذج المفاهيمي

```text
السلسلة التعليمية
 └── الجزء أو المستوى
      ├── كتاب الطالب
      │    └── الوحدات
      │         └── الدروس والأنشطة
      ├── كتاب المعلم
      ├── كتاب التمارين
      └── المواد المصاحبة (صوت، إجابات، بطاقات)

كل كتاب أو مادة ← ملف أصلي واحد أو أكثر
```

| الكيان | التعريف |
|---|---|
| **السلسلة التعليمية** | مجموعة كتب تحت اسم واحد ومنهج واحد |
| **الجزء أو المستوى** | تقسيم داخل السلسلة، مثل المستوى الأول |
| **الكتاب** | وحدة نشر مستقلة لها عنوان ونوع: طالب، معلم، تمارين |
| **الوحدة** | قسم موضوعي داخل الكتاب |
| **الدرس** | جزء من الوحدة له هدف تعليمي محدد |
| **الملف الأصلي** | الملف الفعلي كما استُلم، ولا يُعدّل |
| **المواد المصاحبة** | ملفات تابعة لكتاب أو جزء، ولا معنى لها منفردة |

### قواعد العلاقة

- يُسجل كل ملف تابع لمنهج مرتبطًا بالكتاب أو الجزء الذي ينتمي إليه، ولا يُسجل سجلًا مستقلًا بلا علاقة.
- يُربط كتاب المعلم بكتاب الطالب المقابل بعلاقة صريحة.
- تسجيل الوحدات والدروس اختياري في البداية، ويُضاف عند الحاجة الفعلية إليه.
- الكتاب المستقل الذي لا ينتمي إلى سلسلة يُسجل دون حقل السلسلة.

> هذه بنية تنظيمية مقترحة. قاعدة البيانات الحالية لا تتضمن هذه الكيانات أو علاقاتها.

## 6. قواعد تسمية الملفات وتنظيمها

### الصيغة المقترحة

```text
<السلسلة-أو-العنوان>_<الجزء>_<النوع>_<الطبعة-أو-السنة>.<الصيغة>
```

- أحرف لاتينية صغيرة وشرطات بين الكلمات، دون مسافات أو رموز خاصة، لضمان التوافق مع أنظمة الملفات والروابط.
- يُحفظ العنوان العربي الكامل في البيانات الوصفية، لا في اسم الملف.
- يُذكر الجزء والنوع والطبعة عند انطباقها.
- يُحتفظ بالاسم الأصلي للملف في حقل «الاسم الأصلي» داخل السجل حتى لا تضيع معلوماته.

### الرموز المقترحة للنوع داخل الاسم

`student` · `teacher` · `workbook` · `audio` · `answers` · `guide` · `reference` · `framework`

### أمثلة توضيحية

هذه أمثلة مقترحة، ولا تشير إلى ملفات موجودة بالضرورة.

| قبل | بعد |
|---|---|
| `book-final-new.pdf` | `arabic-series-x_l1_student_2020.pdf` |
| `teacher (2).pdf` | `arabic-series-x_l1_teacher_2020.pdf` |
| `تمارين المستوى الاول نسخة اخيرة.pdf` | `arabic-series-x_l1_workbook_2020.pdf` |
| `audio.zip` | `arabic-series-x_l1_audio_2020.zip` |
| `scan001.pdf` | `title-pending_unknown_reference_unknown.pdf` مع حالة «يحتاج إلى مراجعة» |

### التكرار والطبعات

- **نسخة مطابقة:** يُحتفظ بنسخة واحدة، ويُسجل مصدر النسخة المكررة في السجل نفسه.
- **طبعة مختلفة:** تُسجل سجلًا مستقلًا وتُربط بالطبعة الأخرى، ولا تُحذف أي منهما.
- **نسخة ممسوحة ضوئيًا وأخرى رقمية:** يُحتفظ بالاثنتين إذا اختلفت جودتهما أو قابلية استخراج النص منهما، مع توضيح الفرق.
- **الملف الأصلي لا يُستبدل.** أي نسخة معدّلة، مثل ضغط أو قص أو تحسين، تُحفظ ملفًا مستقلًا ويُوثق التعديل وسببه.

## 7. سير العمل القياسي لإضافة كتاب جديد

| # | الخطوة | المخرج |
|---|---|---|
| 1 | استقبال الملف وتسجيل مصدره | سجل مبدئي بالمصدر وتاريخ الاستلام |
| 2 | التحقق من حقوق الاستخدام | حالة حقوق من القسم 8 |
| 3 | التأكد من عدم وجود نسخة مكررة | البحث بالعنوان والمؤلف والسلسلة والطبعة |
| 4 | مراجعة العنوان والمؤلف واللغة ونوع المحتوى | بيانات أساسية مؤكدة أو معلّمة |
| 5 | تحديد الجمهور والقسم والوسوم | تصنيف كامل |
| 6 | الربط بالسلسلة أو المنهج أو المواد المصاحبة | علاقات موثقة |
| 7 | فحص سلامة الملف وقابليته للفتح والقراءة | ملاحظة عن الجودة وإمكانية استخراج النص |
| 8 | تسجيل البيانات الوصفية | سجل مكتمل وفق القسم 4 |
| 9 | مراجعة التصنيف والحقوق | تأكيد من مراجع ثانٍ عند الإمكان |
| 10 | الاعتماد وفق الصلاحيات المعتمدة | حالة `معتمد` |
| 11 | التحقق من سهولة العثور على المادة | تجربة بحث بثلاثة مداخل مختلفة على الأقل |

### نقاط التوقف

- **بعد الخطوة 2:** إذا كانت الحقوق غير واضحة، تبقى المادة `معلّقة` ولا تُتاح لأي مستخدم.
- **بعد الخطوة 3:** إذا ثبت التكرار، يُحدّث السجل القائم بدل إنشاء سجل جديد.
- **بعد الخطوة 7:** الملف التالف أو غير المقروء لا يُعتمد حتى تتوفر نسخة سليمة.
- **قبل الخطوة 10:** لا يُنشر الكتاب أو يُتاح قبل استكمال التحقق من الحقوق وسلامة المحتوى.

## 8. سياسة حقوق النشر والإتاحة

| الحالة | المعنى | الإتاحة المسموحة |
|---|---|---|
| **مملوك لفُصحاء** | محتوى أنتجه فريق فُصحاء أو يملك حقوقه بوثيقة واضحة | وفق قرار فُصحاء |
| **مفتوح الترخيص** | محتوى بترخيص مفتوح موثق | وفق شروط الترخيص حرفيًا، مع ذكر النسبة والترخيص في السجل |
| **مرخص بإذن** | إذن مكتوب من صاحب الحقوق | في حدود الإذن فقط، ويُحفظ الإذن أو مرجعه |
| **استخدام داخلي** | يُستخدم مرجعًا للفريق | للفريق المخوّل فقط، دون إتاحة للمستخدمين |
| **استخدام المعلم دون إعادة نشر** | يستخدمه المعلم ضمن صلاحياته الخاصة | لا يُعاد نشره أو مشاركته عبر المنصة |
| **غير واضح الحقوق** | لا تتوفر معلومات كافية | **معلّق** حتى التحقق، ولا يُتاح |

### قواعد ثابتة

- امتلاك نسخة PDF لا يعني إذنًا بإعادة نشرها أو بيعها أو تحويلها إلى منتج مدفوع.
- الترخيص المفتوح لا يعني دائمًا السماح بالاستخدام التجاري أو التعديل؛ تُقرأ شروطه نصًا.
- لا يُكتب في السجل ترخيص أو حكم قانوني لم يُتحقق منه. الحالات غير الواضحة تُحال إلى مراجعة مختصة.
- معالجة المحتوى آليًا، مثل استخراج النص أو التحويل إلى أنشطة، تخضع لحالة الحقوق نفسها.

## 9. البحث والتصفية

### متطلبات تنظيمية تُعتمد من البداية

تُسجل هذه البيانات الآن في كل سجل، حتى قبل وجود واجهة بحث، لأن إضافتها لاحقًا إلى مئات الكتب مكلفة:

- العنوان والعنوان الأصلي والمؤلف.
- الجمهور المستهدف.
- نوع الكتاب والقسم الرئيسي.
- المستوى اللغوي.
- المهارة والموضوع والوسوم.
- السلسلة والمنهج والجزء.
- لغة المحتوى.
- صيغة الملف.
- حالة الإتاحة والحقوق.

### وظائف تقنية مستقبلية

- واجهة بحث نصي بالعنوان والمؤلف.
- مرشحات متعددة مجتمعة، مثل المستوى والمهارة والجمهور.
- عرض شجرة السلسلة وموادها المرتبطة.
- البحث داخل نص الكتاب، وهو مشروط بالحقوق وجودة استخراج النص.

## 10. التكامل المستقبلي مع منتجات فُصحاء

كل ما في هذا القسم **إمكانية مستقبلية**. القائم فعليًا هو استخدام ملف PDF أو DOCX قصير مصدرًا لإنشاء درس، وليس ربطًا بمكتبة.

| المنتج | الاستخدام المتوقع |
|---|---|
| **مولّد الدروس التفاعلية** | اختيار وحدة أو نص من كتاب معتمد مصدرًا للدرس بدل رفع الملف في كل مرة |
| **مولّد أوراق العمل والتمارين** | إعداد تدريبات مرتبطة بمفردات وقواعد وحدة محددة |
| **صانع البطاقات التعليمية** | استخراج مفردات وحدة أو كتاب مصور إلى بطاقات |
| **صانع الاختبارات والألعاب اللغوية** | بناء أنشطة قياس مرتبطة بأهداف وحدة أو مستوى |
| **مساعد تحليل صعوبة النصوص** | تقدير ملاءمة نصوص كتب القراءة للمستوى المستهدف |
| **مساعد تحويل المحتوى** | تحويل نص من كتاب إلى أنشطة استماع وتحدث وقراءة وكتابة |
| **مخطط الحصة الذكي** | ربط خطة الحصة بالوحدة والدرس في كتاب الطالب ودليل المعلم |
| **مستودع القوالب والممارسات التعليمية** | ربط القوالب بأنواع الكتب والمهارات التي تناسبها |

### شروط أي معالجة

لا يُفترض أن كل كتاب قابل للتحويل أو المعالجة. قبل أي استخدام آلي يجب التحقق من:

1. أن حالة الحقوق تسمح بالمعالجة المقصودة.
2. أن الملف يسمح باستخراج نص موثوق؛ فالملفات الممسوحة ضوئيًا قد تحتاج إلى معالجة إضافية وقد تكون نتائجها غير دقيقة.
3. أن طبيعة المادة مناسبة، فمواد الخط والصور مثلًا لا تُعامل كنص.
4. أن الحدود التقنية الحالية مراعاة، ومنها حد الصفحتين لملف PDF في إنشاء الدرس.

## 11. أمثلة تطبيقية

الأمثلة التالية توضيحية. لم تُفحص فيها محتويات كتب فعلية، والقيم غير المؤكدة موسومة صراحة.

### المثال الأول: مرجع من نوع CEFR

| الحقل | القيمة |
|---|---|
| المعرّف الداخلي | `FSH-FW-0001` |
| العنوان | الإطار الأوروبي المرجعي المشترك للغات (CEFR) |
| العنوان الأصلي | Common European Framework of Reference for Languages |
| المؤلف | مجلس أوروبا |
| الناشر | يحتاج إلى مراجعة |
| سنة النشر والطبعة | يحتاج إلى مراجعة، لوجود نسخ وإصدارات متعددة |
| نوع المادة | `framework` |
| القسم الرئيسي | مكتبة المعايير والمراجع الأساسية |
| الجمهور المستهدف | المعلمون وفريق المحتوى |
| المجال | المستويات والكفاءة اللغوية |
| لغة المحتوى الفعلية | تُحدد بعد فتح الملف |
| اسم الملف | `cefr_framework_unknown.pdf` إلى أن تُؤكد السنة |
| الاسم الأصلي | يُنقل كما استُلم |
| المصدر | يُسجل الرابط أو الجهة الفعلية |
| حالة الحقوق | غير واضح الحقوق حتى مراجعة شروط الجهة الناشرة |
| حالة المراجعة | `مسودة` |
| الوسوم | `مستويات`، `معايير`، `تقييم` |

ملاحظة: هذا الإطار غير مذكور في وثائق المشروع الحالية، وإدراجه مرجعًا لا يعني أن مستويات المنصة مبنية عليه.

### المثال الثاني: كتاب طالب مرتبط بكتاب معلم ووحدات

```text
السلسلة: سلسلة س لتعليم العربية  (FSH-SR-0001)
 └── المستوى الأول
      ├── كتاب الطالب     FSH-BK-0010  arabic-series-x_l1_student_2020.pdf
      │    ├── الوحدة 1: التعارف
      │    └── الوحدة 2: الأسرة
      ├── كتاب المعلم     FSH-BK-0011  arabic-series-x_l1_teacher_2020.pdf
      │    └── مرتبط بـ: FSH-BK-0010
      └── الملحق الصوتي   FSH-BK-0012  arabic-series-x_l1_audio_2020.zip
           └── تابع لـ: FSH-BK-0010
```

| الحقل | كتاب الطالب | كتاب المعلم |
|---|---|---|
| نوع المادة | `student-book` | `teacher-book` |
| القسم الرئيسي | مكتبة المتعلم | مكتبة المعلم |
| السلسلة | FSH-SR-0001 | FSH-SR-0001 |
| الجزء | المستوى الأول | المستوى الأول |
| المستوى اللغوي | مبتدئ | مبتدئ |
| المواد المرتبطة | FSH-BK-0011، FSH-BK-0012 | FSH-BK-0010 |
| المؤلف | غير معروف، إذا لم يظهر في الملف | غير معروف |
| حالة الحقوق | غير واضح الحقوق حتى التحقق | غير واضح الحقوق حتى التحقق |

**عند غياب معلومة:** يُكمل السجل بما هو مؤكد، وتوضع «غير معروف» أو «يحتاج إلى مراجعة» في بقية الحقول، وتبقى حالة المراجعة `مسودة` حتى تُستكمل الحقول الإلزامية وتُحسم الحقوق.

## 13. حدود الدليل وما يحتاج إلى قرار لاحق

المسائل التالية **قرارات مستقبلية تحتاج إلى دراسة**، ولا تُعد وظائف معتمدة:

1. هل ستسمح المنصة برفع كتب من المعلمين، وبأي مراجعة؟
2. هل ستكون بعض الكتب مجانية وبعضها مدفوعًا، وكيف يرتبط ذلك بنظام الرصيد الحالي؟
3. هل ستتم القراءة داخل المنصة أم عبر تنزيل الملفات؟
4. هل ستتم معالجة محتوى الكتب آليًا، وبأي حدود تتجاوز حد الصفحتين الحالي؟
5. ما الصلاحيات المطلوبة للمعلم والطالب والإدارة؟
6. ما آلية اعتماد المحتوى ومراجعته، ومن يملك صلاحية الاعتماد؟
7. أين تُخزن الملفات الأصلية، وهي مسألة مفتوحة في `PRD.md`؟
8. هل تُسجل الوحدات والدروس داخل الكتب، أم يُكتفى بالكتاب وملحقاته؟
